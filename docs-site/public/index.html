10Qayta yuborish (retry) qoidalari

        

          
JavobNima qilish kerak

          
            
200Natijani o'z tomoningizda ham keshlang (kamida 5–30 daqiqa).

            
400 / 401 / 404 / 405Qayta yubormang. Natija o'zgarmaydi — so'rov yoki tokenni tuzating. 404 ni ham qisqa muddat keshlang.

            
429Retry-After soniya kuting, keyin bitta so'rov yuboring. Parallel oqimlarni kamaytiring.

            
502 / 503 / tarmoq xatosiEksponensial kutish: 1 s → 2 s → 4 s (+ tasodifiy 0–500 ms), ko'pi bilan 3 marta. Keyin foydalanuvchiga xato ko'rsating.

          
        

        
    
          
  • So'rov uchun 8–10 soniya timeout qo'ying.
    • 
          
  • Bir xil id + zone ni bir vaqtda qayta-qayta yubormang — bitta javobni kuting.
    • 
          
  • Foydalanuvchi kiritayotgan har bir harf uchun emas, faqat "Tekshirish" bosilganda so'rov yuboring.
    • 
        

        

          
JavaScript — to'g'ri retry


async function checkMlbb(id, zone) {
  for (let attempt = 0; attempt < 4; attempt++) {
    let res;
    try {
      res = await fetch(`https://mlbb.nurali.uz/v1/check?id=${id}&zone=${zone}`, {
        headers: { Authorization: `Bearer ${process.env.MLBB_API_TOKEN}` },
        signal: AbortSignal.timeout(10_000),
      });
    } catch {
      res = null; // tarmoq xatosi / timeout
    }

    if (res && res.status < 500 && res.status !== 429) return res.json(); // 2xx/4xx — qayta yubormaymiz
    if (attempt === 3) break;

    const wait = res?.status === 429
      ? Number(res.headers.get("retry-after") || 60) * 1000
      : 1000 * 2 ** attempt + Math.random() * 500;
    await new Promise((r) => setTimeout(r, wait));
  }
  throw new Error("MLBB API vaqtincha ishlamayapti");
}
